# Testing

```bash
pnpm test        # unit + integration (node:test, TypeScript run directly, real PostgreSQL via PGlite)
pnpm test:e2e    # Playwright against a fresh production build and a throwaway database/file store
pnpm verify      # lint + typecheck + test + build (what CI runs)
pnpm bench       # performance measurements
```

## Layers

| Layer | Where | What it uses |
|---|---|---|
| Extraction unit tests | `packages/extract/test/extract.test.ts` | Pure functions: dates (Indian, ISO, written, relative, ranges, Devanagari digits), ambiguity flags, money, recurrence, references, receipts → purchase/warranty/return, bills, subscriptions, multi-action messages, promises, prompt-injection, quick add |
| Core unit tests | `packages/core/test/units.test.ts` | Timezones incl. DST gap/overlap, quiet hours, recurrence edge cases, ICS round-trip, ZIP CRC, upload sniffing, SSRF guard, Argon2id, envelope encryption tamper detection, TOTP (RFC 6238 vector), Web Push encryption (decrypted by an independent receiver) and VAPID signature, analytics sanitisation |
| Integration | `flow`, `workflows`, `invariants`, `security`, `modules`, `ocr` tests in `packages/core/test` | Every test creates a fresh in-memory PostgreSQL (PGlite), registers real users (Argon2id at reduced cost), and calls services exactly as the API does. No mocks of the database, crypto, OCR or PDF parsing. |
| End-to-end | `tests/e2e/*.spec.ts` | Production build (`.next-e2e`), embedded PostgreSQL in a temp directory, Chromium desktop for everything; Pixel 7 (Chromium) and iPhone 14 (WebKit) emulation for tests tagged `@cross-browser`; the extension test loads the unpacked MV3 extension in Chromium |

## Mapping to the specification

* **Workflows A–H** — service-level versions in `workflows.test.ts` / `flow.test.ts`, browser versions in `tests/e2e/workflow-*.spec.ts`.
* **Invariants 1–25** — one test each in `invariants.test.ts` (17 references Workflow G).
* **Security tests** — `security.test.ts` (cross-user, cross-family, escalation, invitations, sessions, login limits, MFA, API scopes, billing bypass, export scope, prompt injection, push SSRF, reminder ownership) and `tests/e2e/platform.spec.ts` (401s, CSRF, cross-user page/API, headers).

## Fixtures
`tests/fixtures/screenshot.png` and `receipt.pdf` are generated by `node scripts/make-fixtures.ts` (Chromium renders invented text). E2E tests generate their own images/PDFs at run time. OCR tests need the English model (`pnpm setup:ocr`); without it they are skipped with that reason.

## What is not tested automatically
Real phones (install, share sheet, push), Firefox, the PostgreSQL-server driver, URL fetching against the internet, Razorpay itself, screen readers (labels/landmarks exist but no assistive-technology run), visual regression, load. See [TEST_RESULTS.md](TEST_RESULTS.md) for the latest numbers.

## Gotchas
* E2E builds into `.next-e2e` so a running dev server can't clobber it.
* Playwright is pinned to 1.64.1 to match the locally cached browsers.
* Forms filled before hydration are discarded by React; `register()` retries the submit with `toPass`.
* IP-based rate limits only apply behind a trusted proxy (`LIFEOS_TRUST_PROXY=1`); without one, every client used to share a bucket — E2E caught this.
